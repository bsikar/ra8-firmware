# components-lock.txt -- the esp-idf component set the proven ESP32-C6 image
# resolved, recorded so a later build cannot quietly resolve a different one.
#
# THIS IS A RECORD, NOT A DROP-IN LOCK. Do not copy it over, rename it to, or
# otherwise feed it to the component manager as dependencies.lock: it is not
# that file's format, and it deliberately omits the one field that file has
# which cannot be shared between machines.
#
# Why it exists
# -------------
# build.sh deletes dependencies.lock before every build, so the component
# manager re-resolves from the registry each time. That makes the build
# RECIPE-reproducible -- same script, same pins, same sdkconfig -- but not
# BIT-reproducible: the registry can hand back a different component version
# tomorrow from an unchanged recipe, and without this file nothing would say so.
#
# Why not just commit dependencies.lock
# -------------------------------------
# Because it is not portable. The generated lock records an ABSOLUTE PATH for
# the local cmd_system component, which comes out of the building host's own
# IDF checkout ($IDF_PATH/examples/system/console/advanced/components/
# cmd_system). Committing that would bake one machine's home directory into the
# repository and be wrong everywhere else. What IS portable is the resolved
# SET, which is what the rows below carry.
#
# How it is enforced
# ------------------
# build.sh normalises the freshly generated dependencies.lock to the same four
# columns and diffs it against this file AFTER the build, failing loudly on any
# difference. The local component is compared on kind and version only -- never
# on its path, for the reason above. That turns "recipe-reproducible" into
# "verified-reproducible", which is strictly stronger than pinning alone.
#
# Provenance
# ----------
# Taken from the bench build of esp-hosted-mcu at the pinned commit
# 949bb30612747a3bd9e402eda8d01fbfa1f8503e under esp-idf v5.5.4 -- the build
# whose network_adapter.bin is the image actually flashed on the C6 and proven
# end to end (peripheral firmware 2.12.11, esp-hosted RPC round-trip green).
# The upstream manifest is pinned by ESP_HOSTED_MCU_COMMIT in pins.env. The
# checked-in extension patch also narrows its MQTT dependency to the proven
# 1.0.0 release; this record remains the final assertion over every resolved
# component and registry hash.
#
# Changing a row means re-pinning the C6 image. Update it only together with a
# reflash and a re-run of `just hil::c6`; an edit here on its own just teaches
# the gate to accept whatever drifted.
#
# Columns: kind, name, version, component_hash
#   kind    the generated lock's own source type: service (Espressif component
#           registry), local (a path component from the host IDF checkout), or
#           idf (the framework itself).
#   hash    the registry's component_hash. "-" where the kind has none, which
#           is every non-registry row -- a local path and the framework are
#           identified by version, not by content hash.
