Detailed Description

Deep Software Standby 1 (LPSCR.LPMD = 0x8) entry demo.

Tag
[Ring 6 / APP] {World: S}

Demonstrates Deep Software Standby variant 1 (LPSCR.LPMD = 0x8 per HUM Ch 11.2.20 p 457) on the EK-RA8D2. Unlike Software Standby (LPMD = 0x5), Deep Software Standby resets the CPU on wake instead of resuming – so the wake path lands in Reset_Handler and the banner is re-emitted on every cycle.

Variant 1 keeps the LOCO, sub-clock detection, and voltage monitors running (HUM Ch 11.1 Table 11.3 p 431..432). Variants 2 and 3 (in sibling demos) progressively turn more domains off.

Boot flow:

  1. CGC + SysTick + UART (SCI8) bring-up.
  2. Emit boot banner "lpm_dpsby1: boot\r\n" – HIL gate.
  3. RTC init + seed + arm a +5 s alarm + RCR1.AIE.
  4. Arm DPSIER2.DRTCAIE so the alarm cancels Deep Standby.
  5. Arm WUPEN0.RTCALMWUPEN so the alarm reaches the wake matrix.
  6. ra8_lpm_enter_sleep(k_ra8_sleep_mode_deep_standby_1).

The chip resets on wake – the next boot lands back in step 1.

SOSC caveat
Same SOSC dependency as lpm_software_standby_demo (see that file's header). If the sub-clock crystal is silent the wake never happens; the HIL gate is boot-banner-only so the firmware build
  • bring-up path is still exercised.
