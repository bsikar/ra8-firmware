[7] J-LINK OB SWDMD VIA UART -- TESTED, DOES NOT DRIVE MD ON THIS EK
================================================================
Some EK-RA8 boards (EK-RA8M1, EK-RA8D1) wire SWDMD from the
on-board J-Link OB to the MCU's MD pin so that rfp-cli with
-if uart auto-enters SCI boot mode without physical jumper
manipulation. Tested on this EK-RA8D2 v1 board:

  $ rfp-cli -d ra -tool jlink:1086567198 -if uart -s 115200 -rfo
  Renesas Flash Programmer CLI V1.15
  Connecting the tool (J-Link)
        J-Link Firmware: J-Link OB-RA4M2 compiled Dec 10 2025 15:52:53
  Tool: J-Link (SEGGER J-Link (unknown))
  Interface: 2 wire UART
  Connecting the target device
  [Error] E3000105: The device is not responding.
  Disconnecting the tool

Per the EK-RA8D2 v1 User's Manual (R20UT5523EG0101 Rev 1.01,
Oct 2025), the J-Link OB on this board does NOT have any
control over MD pin via SWDMD. Physical access to the J16
jumper is the only path into the boot ROM on this EK board.

[8] WHAT WAS TRIED AND FAILED FOR RECOVERY
================================================================
1. JLinkExe RSetType 0, 1, 2, 3 at speeds 100 kHz, 1 MHz, 4 MHz
   -- all fail with "CPU could not be halted" / "Could not power
   up DAP"
2. JLinkExe `r` (RA-specific reset that goes via secure-domain
   SYSRESETREQ) -- "Reset: SYSRESETREQ has confused core",
   "Could not halt CPU after reset"
3. JLinkExe RnReset (assert nSRST pin) + halt -- same result
4. rfp-cli -erase-chip -- clears MRAM but not DLM
5. rfp-cli -dlm to every documented state -- E3000902
6. rfp-cli -dlm OEM_PL0 (the chip is already there) -- "Operation
   successful" but subsequent reads still fail
7. Hard power cycle via Tapo smart plug, 45 s and 60 s off
   durations -- DLM state survives (it is in non-volatile OFS)
8. USB PPPS port cycling (all 4 EK-RA8D2 USB ports) -- chip
   stays powered through alternate USB cables; no chip reset
9. rfp-cli -auth AL2KEY <21 common defaults> -dlm SSD -- all
   "Authentication failure"
10. rfp-cli -tool jlink -if uart -rfo -- E3000105 (J-Link OB does
    not drive MD on this EK board variant)
