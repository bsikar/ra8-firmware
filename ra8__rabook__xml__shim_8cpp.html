Detailed Description

C++ -> C shim: tinyxml2 XHTML parser -> ra8_rabook DOM builder (#149).

Wraps tinyxml2 to parse an XHTML chapter file and build the ra8_rabook_ctx_t DOM that ra8_rabook_compile.h serialises. The iterative DFS walk mirrors DomBuilder.add_element() in the desktop tool tools/epub_compile/epub_compile.py:

  • Element nodes: tag name + source-order attributes.
  • Text nodes: verbatim character data (entities resolved by tinyxml2).
  • Comments / PIs / CDATA: silently skipped.
DFS pre-order (correct left-to-right, depth-first):
When a node N is popped, its next_sibling is pushed (before first_child). Because first_child is pushed last it is popped first, giving: N, N's subtree, N's next_sibling, N's next_sibling's subtree – exactly the pre-order the desktop tool's recursive implementation produces.
NASA Rule 1 (no recursion): RA8_NO_RECURSION documented below.
NASA Rule 3 deviation: tinyxml2 XMLDocument heap (bounded, local).

◆ ra8_xhtml_limits_t

enum ra8_xhtml_limits_t : uint16_t

Static bounds for the iterative DFS to satisfy NASA Rule 2.

Every turn of s_walk_body_subtree pops one frame and pushes at most two (next_sibling, then first_child), so the stack grows by one frame only where the walk descends into a first_child whose parent also had a next_sibling. A pure sibling step is net zero: it pops one frame and pushes one. The high-water mark is therefore the node-depth of the deepest node measured from <body> – depth + 1, NOT 2 * depth.

tinyxml2 bounds that depth: it aborts the parse once the tracked nesting reaches TINYXML2_MAX_ELEMENT_DEPTH, so the deepest node it admits sits at absolute depth TINYXML2_MAX_ELEMENT_DEPTH - 1 and <body> itself occupies absolute depth >= 1. The reachable high-water mark is thus at most TINYXML2_MAX_ELEMENT_DEPTH - 2 frames – 498 against the vendored cap of 500, measured exactly by test_deep_at_tinyxml2_cap.

Parse one XHTML chapter and add it to the builder context.

Parses xhtml_bytes with tinyxml2, locates the <body> subtree (or falls back to the document root), and performs an iterative DFS pre-order walk that mirrors the desktop tool's DomBuilder.add_element() recursion:

  • Element nodes become ra8_rabook_add_element calls (name + attrs).
  • Text nodes become ra8_rabook_add_text calls (interned string).
  • Comments, PIs, and CDATA are silently skipped.

On return, ra8_rabook_add_chapter(ctx, title_off, href_off, root_idx) has been called and the chapter is recorded in the builder.

NASA Rule 1 (no recursion)
The DFS uses an explicit caller-stack of capacity 512 frames (k_xhtml_max_stack in the implementation; no C recursion; documented with RA8_NO_RECURSION).
NASA Rule 3 (no dynamic allocation) – documented deviation
tinyxml2::XMLDocument::Parse() heap-allocates its internal node pool. The document is local to this function and freed on return, so no allocation outlives the call. This is the same exemption accepted by libs/ra8_epub/src/ra8_epub_xml_shim.cpp.
