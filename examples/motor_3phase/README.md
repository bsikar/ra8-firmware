# motor_3phase

Three-phase synchronized PWM demo for the EK-RA8D2. Opens GPT0 / GPT1
/ GPT2 as a U/V/W triple via `ra_gpt_three_phase_open`, programmes a
1 us dead-time pair on each channel, and sweeps the duty cycles
through a 256-sample sine table once every ~2 seconds. The duty
values are reported every 100 ms over the J-Link OB CDC port (SCI8
@ 115200).

## Status: untested on hardware

The application compiles clean and exercises the full driver API
end-to-end (`ra_gpt_three_phase_open`, `ra_gpt_pwm_pin_configure`,
`ra_gpt_dead_time_set`, `ra_gpt_three_phase_set_duty`,
`ra_gpt_three_phase_close`) but the EK-RA8D2 v1 J-tag header pin
allocation for an external motor-driver IC was **not** confirmed
against the User's Manual at authoring time. Update
`k_motor_3phase_pin_u/v/w` in `main.c` once the manual table is
checked.

## J-tag connector mapping (placeholder)

The expected flow for an external 3-phase driver IC (e.g.
DRV8323 / FAN73833 / IRS2336) is:

```
GTIOC0A (U-phase) -- J-tag pin TBD -> driver IN_U
GTIOC1A (V-phase) -- J-tag pin TBD -> driver IN_V
GTIOC2A (W-phase) -- J-tag pin TBD -> driver IN_W
```

The complementary low-side outputs are produced inside the driver
IC by inverting INx with a built-in dead-time, so the firmware only
emits the three high-side gate signals from the GTIOCnA pins.

For boards that need both rails generated by the MCU instead, the
GTIOCnB pins of the same channels carry the inverted signals
automatically when `ra_gpt_dead_time_set` is non-zero (HUM Ch 22.5
"Complementary PWM Mode").

## Build + flash

From the repo root:

```sh
make motor_3phase                       # cross-compile
make -C examples/motor_3phase flash     # flash via on-board J-Link OB
```

Or standalone:

```sh
cd examples/motor_3phase/
make
make flash
make clean
```

## What the firmware does

1. `ra_cgc_init()` brings up XTAL + PLL1 (CPUCLK0 = 1 GHz, PCLKA =
   125 MHz, PCLKD = 125 MHz).
2. `ra_pfs_route_peripheral()` routes `PD02 / PD03` to SCI8 and
   the three placeholder GTIOCnA pins to GPT.
3. `ra_sci_init(8, 115200 8N1)` opens the J-Link diagnostic stream.
4. `ra_mstp_init()` then `ra_gpt_three_phase_open()` arms GPT0 /
   GPT1 / GPT2 with triangle-wave PWM, prescaler / 1, period =
   0xFFFF (~1.91 kHz carrier at PCLKD = 125 MHz). GTSTR is written
   in one transaction so the three counters start synchronized.
5. `ra_gpt_pwm_pin_configure(ch, A, ...)` sets active-high polarity,
   stop-low, and POEG-fault-Hi-Z behaviour for each output.
6. `ra_gpt_dead_time_set(ch, 125, 125)` programmes 125 PCLKD ticks
   of rising + falling dead-time (1 us at 125 MHz). The driver
   asserts GTDTCR.TDE so the silicon honours the dead-time pair.
7. `ra_gpt_three_phase_set_duty(50%, 50%, 50%)` is the initial
   test pattern -- a 50 % duty square wave at the carrier rate
   on each phase.
8. Loop: every 8 ms advance the sine-table phase by one step,
   compute the new U/V/W duty cycles via the 120-degree-shifted
   sine entries, and push the triple through
   `ra_gpt_three_phase_set_duty`. Every 100 ms print the current
   duty cycles on SCI8 and toggle LED1.

## Sine table

The 256-entry sine LUT is built at startup using a fixed-point
Bhaskara I approximation:

```
sin(x) ~= 16 * x * (pi - x) / (5 * pi^2 - 4 * x * (pi - x))   for x in [0, pi]
```

We avoid floating-point so the firmware does not pull in a
soft-FP sin() implementation. The output is shifted into
`[0, period]` so the values feed directly into
`ra_gpt_three_phase_set_duty`.

## Connecting a terminal to SCI8

```sh
picocom -b 115200 /dev/cu.usbmodem...
```

You should see `duty UVW <u> <v> <w>` once every 100 ms.

## Debugging

```sh
make -C examples/motor_3phase ozone
make -C examples/motor_3phase debug
```

Useful SWD probes (HUM Ch 22 register window):

```
mem32 0x40169000 1   # GPT0 GTCR    -- mode + prescaler + CST
mem32 0x40169004 1   # GPT0 GTPR    -- period
mem32 0x4016904C 1   # GPT0 GTCCRA  -- live duty
mem32 0x4016908C 1   # GPT0 GTDTCR  -- dead-time enable
mem32 0x40169090 1   # GPT0 GTDVU   -- rising dead-time count
mem32 0x40169094 1   # GPT0 GTDVD   -- falling dead-time count
mem32 0x40169100 1   # GPT1 GTCR
mem32 0x40169200 1   # GPT2 GTCR
```
