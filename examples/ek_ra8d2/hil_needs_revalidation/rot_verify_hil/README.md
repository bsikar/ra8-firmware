# rot_verify_hil

On-silicon **root-of-trust image verify** on the EK-RA8D2. Runs the real
`ra8_rot` verify chain against a signed fixture and proves a working root of
trust can authenticate images on this hardware:

1. SHA-256 of the image body (software backend; the RSIP hash hardware is dead).
2. Anti-rollback version-bind: `SHA-256(img_version_le || body_digest)` (T5-05).
3. ECDSA-P256 signature check via **tf-psa-crypto** (`ra8_psa_verify_hash`),
   against the RoT public key provisioned in `libs/ra8_dfu/src/ra8_rot.c`.

It also flips one body byte and confirms the tampered image is **rejected**.

This is a **self-test** -- it does NOT enable the root of trust in the boot path
(`RA8_ENABLE_ROOT_OF_TRUST` is scoped to this app's CMake target only), so there
is no risk of bricking the board. It is the on-silicon proof that must pass
before the production DFU / secure-boot path enables authentication.

The fixture `src/rot_fixture.h` is generated by `tools/rot_sign.py` with the
project RoT signing key (kept out of tree). The app compiles `ra8_psa_crypto.c` +
`ra8_rot.c` directly with `RA8_ENABLE_ROOT_OF_TRUST` and links a standalone
`tfpsa_arm` static library (same recipe as `psa_crypto_hil`).

- **LED1** pulses on every PASS; **LED2** latches on failure.
- `rot verify: PASS` / `rot verify: FAIL` over SCI8 (115200 8N1); `hil.conf`
  scrapes it.

```
make rot_verify_hil
make hil-flash APP=rot_verify_hil
```
