Detailed Description

Write-to-temp-then-rename so a failed re-fetch cannot destroy good data.

Every writer in this tool used to open its destination directly and remove() it when anything went wrong. That is a data-loss bug, not merely untidy: re-fetching a page, re-exporting a chapter, or re-running any of it TRUNCATES the previously-good file the moment fopen(path, "wb") succeeds, and then deletes the remains when the network request fails. The user loses a file they already had because a server returned 503.

These three calls are the fix and the whole of it. A writer builds a sibling temp path, writes the new bytes there, and renames it over the destination only once a COMPLETE good copy exists. rename() is atomic within a filesystem, so a reader sees either the old file or the new one and never a half-written one – and on any failure path the destination is never touched at all.

The temp name is a .mdl-tmp-<pid>- PREFIX on the leaf, not a suffix, deliberately:

  • It keeps the destination's extension intact, which matters because two export paths shell out to tools that sniff it – rar appends .rar to an argument it does not recognise as already having one.
  • A leading dot is what list_pages() and the AppleDouble filter already skip, so a temp file living briefly in a chapter directory cannot be packaged as a page.
  • It is a sibling, so the rename() stays within one filesystem. A temp in /tmp would cross a mount point and fail with EXDEV.

The <pid> makes two concurrent media_dl runs writing the same destination collide on the rename (last writer wins, atomically) rather than on the partial file (which would interleave two half-downloads into one corrupt output).

◆ mdl_atomic_abort()

void mdl_atomic_abort ( const char * tmp_path)

Discard a failed attempt, leaving the destination untouched.

The abort half, for every failure path between mdl_atomic_tmp_path and mdl_atomic_commit. Removing the temp is a courtesy – the correctness property is that the destination was never opened – so a removal that itself fails is not reported: there is no useful recovery, and the caller is already returning an error for the real problem.

Parameters
[in]tmp_pathTemp file to discard, or NULL (then a no-op).
Returns
Nothing.
Precondition
tmp_path is NULL or a NUL-terminated path from mdl_atomic_tmp_path.
Every stream that was writing tmp_path is already closed.
Postcondition
No file named tmp_path remains (best effort).
The corresponding destination has not been modified.
Note
Thread-safe: touches only the named path.

bool mdl_atomic_commit ( const char * tmp_path,
const char * final_path )

Rename a completed temp file over its destination.

The commit half. Call this ONLY once the temp file holds a complete, good copy – everything before this point is reversible, and everything after it has replaced the user's data. On a failed rename the temp file is removed so no debris is left behind; the destination is untouched either way, because rename() that fails does not modify its target.

Parameters
[in]tmp_pathTemp file from mdl_atomic_tmp_path (never NULL).
[in]final_pathDestination to replace (never NULL).
Returns
Whether the destination now holds the new bytes.
Return values
trueThe rename succeeded; tmp_path no longer exists.
falseThe rename failed; tmp_path was removed and final_path still holds whatever it held before (possibly nothing).
Precondition
tmp_path and final_path are non-NULL and NUL-terminated.
tmp_path names a COMPLETE output – every stream is closed and every write has been checked.
Postcondition
No file named tmp_path remains, on either outcome.
On false, final_path is byte-for-byte what it was on entry.
Note
Thread-safe: touches only the two named paths.

bool mdl_atomic_tmp_path ( const char * final_path,
char * out,
size_t cap )

Build the sibling temp path a writer should produce its output at.

Returns <dir>/.mdl-tmp-<pid>-<leaf> for a <dir>/<leaf> destination, or .mdl-tmp-<pid>-<leaf> when final_path names a bare leaf. The result is in the destination's own directory so mdl_atomic_commit can rename it without crossing a filesystem boundary.

Parameters
[in]final_pathDestination the caller ultimately wants (never NULL).
[out]outBuffer receiving the temp path (never NULL).
[in]capCapacity of out in bytes.
Returns
Whether a temp path was built.
Return values
trueout holds a NUL-terminated sibling temp path.
falseAn argument was NULL/empty, or the path did not fit in cap.
Precondition
final_path and out are non-NULL; final_path is NUL-terminated.
cap is large enough for the destination plus the ~24-byte prefix.
Postcondition
On true, out is NUL-terminated and differs from final_path.
On false, nothing was created and the caller must not write anything.
Note
Thread-safe: writes only caller-provided storage.
Warning
A false return must ABORT the write. Falling back to writing final_path directly reintroduces exactly the data-loss bug this file exists to remove.
Example:
char tmp[PATH_MAX];
if (!mdl_atomic_tmp_path(out_path, tmp, sizeof(tmp))) {
return k_ra8_fail;
}
FILE* fp = fopen(tmp, "wb");
...
if (failed) {
mdl_atomic_abort(tmp);
return k_ra8_fail;
}
return mdl_atomic_commit(tmp, out_path) ? k_ra8_ok : k_ra8_fail;
