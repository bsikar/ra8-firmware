Detailed Description

Build a FAT16 SD-card image carrying a single font file, written through the real ra8_fs so ra8_emulator's app reads it back bit-for-bit.

ra8_emulator's --sd flag attaches a raw FAT image to the modelled SD card. The firmware app (sd_font_render) mounts that image with ra8_fs and reads a font off it. To guarantee the on-card layout is exactly what ra8_fs expects, this host tool formats the image with the SAME ra8_fs code path: it lays down a minimal FAT16 BPB, mounts it through a memory-backed ra8_fs_backend_t, writes the host font file as FONT.OTF, then dumps the buffer to the output image. Mirrors the in-test image builder in tests/test_ra8_sdmmc_card_reflow.c so the two stay in lock-step.

Usage: mkfontimg <font-in> <image-out> [dest-name]

  • font-in host path to the source font (.otf/.ttf)
  • image-out path of the raw FAT image to write
  • dest-name 8.3 name on the card (default FONT.OTF)

Or: mkfontimg –blank <image-out> Writes a formatted-but-empty FAT16 image (no font) – the "random card" case used to exercise ra8_sdfont_load's self-provisioning path.

Format a 4 MiB FAT16 image, optionally write a font, dump to disk.

Allocates the zeroed sector store, lays the BPB (build_fat16), mounts it through the memory-backed ra8_fs backend, writes font as dest_name when one is supplied (write_font_file), unmounts, and dumps the buffer to image_out (dump_image). The disk buffer is freed on every path. A NULL font produces a formatted-but-empty card.

Parameters
[in]image_outOutput path for the raw FAT image.
[in]fontFont bytes to write, or NULL for a blank card.
[in]font_lenLength of font (ignored when font is NULL).
[in]dest_name8.3 name on the card (ignored when font is NULL).
Returns
0 on success, 1 on any allocation / ra8_fs / I/O failure.
Return values
0The image was formatted, populated and written.
1Allocation, mount, font write, or dump failed (reported on stderr).
Precondition
image_out is a writable path.
font_len describes font when font is non-NULL.
Postcondition
The disk buffer is allocated and freed within this call.
On success image_out holds the raw FAT16 image.
Note
Not thread-safe; the tool is single-threaded.

Lay down a minimal FAT16 BPB on the zeroed image.

Writes just the BPB fields ra8_fs needs to recognise and mount the volume – bytes-per-sector, sectors-per-cluster, reserved count, FAT count, root-entry count, total sectors and FAT size – plus the 0x55AA boot signature. Mirrors the in-test image builder in tests/test_ra8_sdmmc_card_reflow.c so the two stay in lock-step. The buffer must already be zeroed by the caller.

Parameters

Precondition
b is non-NULL with at least one 512-byte sector.
b is zero-initialised before the call.
Postcondition
b carries a mountable FAT16 BPB and boot signature.
Only BPB fields and the signature bytes are set; the rest stays zero.
Note
Not thread-safe; the tool is single-threaded.

Write a little-endian uint16 into the BPB at a byte offset.

Stores v as two bytes, low byte first, at p[off]. FAT BPB fields are little-endian regardless of host endianness, so the bytes are assembled by hand rather than through a struct overlay.

Parameters
[out]pBase of the image buffer being built.
[in]offByte offset of the field within p.
[in]vThe 16-bit value to store little-endian.
Precondition
p is non-NULL with at least off + 2 bytes.
off is a valid BPB field offset.
Postcondition
p[off] and p[off + 1] hold v low byte first.
No other bytes of p are touched.
Note
Not thread-safe; the tool is single-threaded.

Reads at most k_font_cap bytes and rejects anything shorter than k_font_min_bytes, which is the smallest input that could plausibly be a font rather than a truncated file. The caller owns the returned buffer.
