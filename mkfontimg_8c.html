Detailed Description

Build a FAT16 SD-card image carrying a single font file, written through the real ra8_fs so ra8_emulator's app reads it back bit-for-bit.

ra8_emulator's --sd flag attaches a raw FAT image to the modelled SD card. The firmware app (sd_font_render) mounts that image with ra8_fs and reads a font off it. To guarantee the on-card layout is exactly what ra8_fs expects, this host tool formats the image with the SAME ra8_fs code path: it lays down a minimal FAT16 BPB, mounts it through a memory-backed ra8_fs_backend_t, writes the host font file as FONT.OTF, then dumps the buffer to the output image. Mirrors the in-test image builder in tests/test_ra8_sdmmc_card_reflow.c so the two stay in lock-step.

Usage: mkfontimg <font-in> <image-out> [dest-name]

  • font-in host path to the source font (.otf/.ttf)
  • image-out path of the raw FAT image to write
  • dest-name 8.3 name on the card (default FONT.OTF)

Or: mkfontimg –blank <image-out> Writes a formatted-but-empty FAT16 image (no font) – the "random card" case used to exercise ra8_sdfont_load's self-provisioning path.

◆ slurp_font()

uint8_t * slurp_font ( const char * font_in,
size_t * font_len )
static

Read a source font into a freshly allocated buffer.

Reads at most k_font_cap bytes and rejects anything shorter than k_font_min_bytes, which is the smallest input that could plausibly be a font rather than a truncated file. The caller owns the returned buffer.

Parameters
[in]font_inPath to the source font.
[out]font_lenReceives the byte count read, on success only.
Returns
Malloc'd font bytes, or NULL when the font cannot be read.
Return values
NULLAllocation failed, the file is missing, or it is too short.
Precondition
font_in and font_len are non-NULL.
The process may allocate k_font_cap bytes.
Postcondition
On success the caller owns the buffer and must free() it.
On failure nothing is allocated and the input stream is closed.
Note
Not thread-safe; the tool is single-threaded.

Write font onto the mounted card under dest_name.

Goes through the real ra8_fs writer rather than poking the image directly, so the on-card layout is exactly what the firmware app will later read. A NULL font is the blank-card case and succeeds without writing.

Parameters
[in,out]mntMounted volume to write into.
[in]fontFont bytes, or NULL to leave the card empty.
[in]font_lenLength of font (ignored when font is NULL).
[in]dest_name8.3 name to create on the card.
Returns
0 on success, 1 on any ra8_fs failure (diagnosed on stderr).
Precondition
mnt is a successfully mounted volume.
dest_name is a valid 8.3 name when font is non-NULL.
Postcondition
On success the file exists on the card and is closed.
On failure the caller still owns the image buffer and must free it.
Note
Not thread-safe; the tool is single-threaded.
