Detailed Description

Deterministic xorshift32 rand()/srand() override.

Tag
[Ring 1 / Core] {World: S}

Newlib's rand()/srand() heap-allocate per-thread state on first call, which trips the project's ra8_sbrk_trap (NASA Power of 10 Rule 3). NetX Duo and other vendor stacks call rand() for ISN/cookie/jitter generation, so we need a working rand() but cannot tolerate malloc.

This translation unit provides strong overrides for:

  • int rand(void)
  • void srand(unsigned int seed)

The implementation is a single xorshift32 state in BSS. It satisfies RAND_MAX (>= 32767) per ISO C and never returns the same sequence twice in a row from a non-zero seed. It is NOT cryptographically secure – callers needing CSPRNG must go through ra8_rsip TRNG.

Linker note: because newlib's rand/srand live in libc.a, the ld-evaluation order matters. As long as ra8_core/ is on the link line BEFORE -lc, our strong symbols win and newlib's heap path is never reached.

int rand ( void )

Strong override for newlib rand() – xorshift32 step.

Replaces newlib's heap-backed rand() with one xorshift32 advance. NOT cryptographically secure – callers needing a CSPRNG must go through ra8_rsip TRNG.

Returns
Pseudo-random value in [0, RAND_MAX].
Return values
0..RAND_MAXNext xorshift32 output.
Precondition
srand() has been called at least once OR the default seed is acceptable to the caller.
Linker pulls this strong symbol in before -lc.
Postcondition
s_state advances by one xorshift32 step.
Return value lives in [0, RAND_MAX].
Note
Not thread-safe – single shared state word.
Since
0.1.0

◆ srand()

void srand ( unsigned int seed)

Strong override for newlib srand() – xorshift32 seed.

Replaces newlib's heap-backed srand() with a direct write to the xorshift32 state word. A zero seed is silently mapped to k_ra8_rand_default_seed to avoid xorshift's all-zero lockup state.

Parameters
[in]seedInitial state. Zero rewritten to default seed.
Precondition
None.
Linker pulls this strong symbol in before -lc.
Postcondition
s_state is non-zero.
Subsequent rand() results follow the new seed.
Note
Not thread-safe – single shared state word.
Since
0.1.0
