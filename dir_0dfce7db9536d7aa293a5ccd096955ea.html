 Three-phase GPT PWM motor demo for EK-RA8D2 (GPT0/1/2 -> U/V/W).

Detailed Description

Three-phase synchronized PWM demo for the EK-RA8D2. Opens GPT0 / GPT1 / GPT2 as a U/V/W triple via ra8_gpt_three_phase_open, programmes a 1 us dead-time pair on each channel, and sweeps the duty cycles through a 256-sample sine table once every ~2 seconds. The duty values are reported every 100 ms over the J-Link OB CDC port (SCI8 @ 115200).

Status: untested on hardware

The application compiles clean and exercises the full driver API end-to-end (ra8_gpt_three_phase_open, ra8_gpt_pwm_pin_configure, ra8_gpt_dead_time_set, ra8_gpt_three_phase_set_duty, ra8_gpt_three_phase_close) but the EK-RA8D2 v1 J-tag header pin allocation for an external motor-driver IC was not confirmed against the User's Manual at authoring time. Update k_motor_3phase_pin_u/v/w in main.c once the manual table is checked.

J-tag connector mapping (placeholder)

The expected flow for an external 3-phase driver IC (e.g. DRV8323 / FAN73833 / IRS2336) is:

GTIOC0A (U-phase) -- J-tag pin TBD -> driver IN_U
GTIOC1A (V-phase) -- J-tag pin TBD -> driver IN_V
GTIOC2A (W-phase) -- J-tag pin TBD -> driver IN_W

The complementary low-side outputs are produced inside the driver IC by inverting INx with a built-in dead-time, so the firmware only emits the three high-side gate signals from the GTIOCnA pins.

For boards that need both rails generated by the MCU instead, the GTIOCnB pins of the same channels carry the inverted signals automatically when ra8_gpt_dead_time_set is non-zero (HUM Ch 22.5 "Complementary PWM Mode").

Build + flash

From the repo root:

make motor_3phase # cross-compile
make -C examples/motor_3phase flash # flash via on-board J-Link OB

Or standalone:

cd examples/_unsupported/motor_3phase/
make
make flash
make clean

What the firmware does

  1. ra8_cgc_init() brings up XTAL + PLL1 (CPUCLK0 = 1 GHz, PCLKA = 125 MHz, PCLKD = 125 MHz).
  2. ra8_pfs_route_peripheral() routes PD02 / PD03 to SCI8 and the three placeholder GTIOCnA pins to GPT.
  3. ra8_sci_init(8, 115200 8N1) opens the J-Link diagnostic stream.
  4. ra8_mstp_init() then ra8_gpt_three_phase_open() arms GPT0 / GPT1 / GPT2 with triangle-wave PWM, prescaler / 1, period = 0xFFFF (~1.91 kHz carrier at PCLKD = 125 MHz). GTSTR is written in one transaction so the three counters start synchronized.
  5. ra8_gpt_pwm_pin_configure(ch, A, ...) sets active-high polarity, stop-low, and POEG-fault-Hi-Z behaviour for each output.
  6. ra8_gpt_dead_time_set(ch, 125, 125) programmes 125 PCLKD ticks of rising + falling dead-time (1 us at 125 MHz). The driver asserts GTDTCR.TDE so the silicon honours the dead-time pair.
  7. ra8_gpt_three_phase_set_duty(50%, 50%, 50%) is the initial test pattern – a 50 % duty square wave at the carrier rate on each phase.
  8. Loop: every 8 ms advance the sine-table phase by one step, compute the new U/V/W duty cycles via the 120-degree-shifted sine entries, and push the triple through ra8_gpt_three_phase_set_duty. Every 100 ms print the current duty cycles on SCI8 and toggle LED1.

Sine table

The 256-entry sine LUT is built at startup using a fixed-point Bhaskara I approximation:

sin(x) ~= 16 * x * (pi - x) / (5 * pi^2 - 4 * x * (pi - x)) for x in [0, pi]

We avoid floating-point so the firmware does not pull in a soft-FP sin() implementation. The output is shifted into [0, period] so the values feed directly into ra8_gpt_three_phase_set_duty.

Connecting a terminal to SCI8

picocom -b 115200 /dev/cu.usbmodem...

You should see duty UVW <u> <v> <w> once every 100 ms.

Debugging

make -C examples/motor_3phase ozone

Useful SWD probes (HUM Ch 22 register window):

mem32 0x40169000 1 # GPT0 GTCR -- mode + prescaler + CST
mem32 0x40169004 1 # GPT0 GTPR -- period
mem32 0x4016904C 1 # GPT0 GTCCRA -- live duty
mem32 0x4016908C 1 # GPT0 GTDTCR -- dead-time enable
mem32 0x40169090 1 # GPT0 GTDVU -- rising dead-time count
mem32 0x40169094 1 # GPT0 GTDVD -- falling dead-time count
mem32 0x40169100 1 # GPT1 GTCR
mem32 0x40169200 1 # GPT2 GTCR

BSP usage

Uses ra8_board_ek_ra8d2 BSP for LED1 init/toggle (P600 per EK-RA8D2 v1 UM Table 24 p 31). The three placeholder GPT output pins are not wired to a specific EK-RA8D2 connector in main.c – choose any GPT- capable pad on the Arduino header (UM Table 20 p 27/28) or Pmod ports (UM Tables 17 / 19 p 26/27) when targeting a real driver IC.

Validated 2026-05-02 against EK-RA8D2 v1 User's Manual (R20UT5523EG0101 Rev 1.01) Table 24 p 31 + Table 20 p 27 (Arduino GTIOC routings), and HUM (R01UH1065EJ0130) Ch 22 "General PWM Timer (GPT)".
