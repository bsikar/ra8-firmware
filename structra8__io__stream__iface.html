Detailed Description

Opaque to applications – backends implement this internally and export a binding helper through their own header.

One vtable per byte-sink.

The concrete vtable layout lives in src/ra8_io_stream_internal.h. Apps never construct one; they call a sink's _init() helper, which binds the sink's const vtable into a caller-owned ra8_io_stream_t.

Since
0.1.0

Each callback receives the sink's opaque ctx so sinks keep their state private.

write is mandatory. flush may be NULL for sinks that have no buffering; the dispatcher maps a NULL flush to success.

Invariant
write is non-NULL.

0.1.0
