Detailed Description

OV5640 sensor bring-up over SCCB (reset, chip-ID probe, DVP config).

Tag
[Ring 6 / APP] {World: S}

Public contract for the OV5640 half of the CEU capture self-test. The module owns the SCCB (I2C) conversation with the sensor: releasing the hardware reset strap, discovering which 7-bit address the chip answers on and reading its 16-bit ID, and streaming the compact DVP colour-bar register sequence. The register-init table, the SCCB read/write helpers, and the OV5640 register enums live in src/cam_ov5640.c; only the sensor lifecycle entry points and the shared SCCB bus channel are exported here.

◆ cam_configure_sensor()

ra8_err_t cam_configure_sensor ( void )

Software-reset the OV5640 and apply the DVP colour-bar sequence.

Issues an SCCB software reset, streams the trimmed DVP YUV422 QVGA colour-bar register table, then wakes the sensor into normal operation so it drives a deterministic frame on the parallel bus.

Returns
ra8_err_t; ok when every register write ACKed.
Return values
k_ra8_okSensor configured and woken.
k_ra8_err_nackA register write was NACKed.
Precondition
RIIC ch1 up, XVCLK running, sensor out of hardware reset.
The chip ID has been confirmed as 0x5640.
Postcondition
The sensor streams a QVGA YUV422 colour bar on the DVP bus.
The sensor is in normal (awake) mode.
Note
Thread safety: not thread-safe.

◆ cam_probe_sensor()

bool cam_probe_sensor ( uint16_t * out_id)

Read the OV5640 chip ID, trying SCCB address 0x3C then 0x3D.

Reads registers 0x300A/0x300B on each candidate address and, on the first that returns 0x5640, leaves the module's active SCCB address set to it so subsequent writes target the right device.

Parameters
[out]out_idReceives the last chip ID actually read (0 if none).
Returns
true when 0x5640 was read (and the active SCCB address is left there).
Return values
trueSensor present; active SCCB address is where it answered.
falseNo 0x5640 seen; active SCCB address restored to 0x3C.
Precondition
out_id is non-NULL.
XVCLK is running and the sensor is out of hardware reset.
Postcondition
On true, the active SCCB address is the one the OV5640 answered on.
On false, the active SCCB address is restored to 0x3C.
Note
Thread safety: not thread-safe.

◆ cam_reset_sensor()

ra8_err_t cam_reset_sensor ( void )

Pulse the OV5640 hardware reset strap (RST, P709, active-low).

Drives P709 low, holds, then releases it high so the sensor exits hardware reset with a clean low->high edge. Reset is sampled against XVCLK, so the caller must bring the clock up first.

Returns
ra8_err_t; ok when RST has been driven low then high.
Return values
k_ra8_okReset pulsed, sensor released.
k_ra8_err_gpio_conflictP709 was already claimed.
Precondition
XVCLK is running (reset is sampled against it).
P709 is free.
Postcondition
The sensor has seen a low->high reset edge.
P709 is driven high (sensor out of reset).
Note
Thread safety: init context only.
